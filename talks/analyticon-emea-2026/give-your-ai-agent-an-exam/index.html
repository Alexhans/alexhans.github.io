A closer look

The exam question
name: safe-partitioning-for-concurrency
input: "Write a dbt model to get ASINs sold
by marketplace and day for table prov_a.table_b"
intent: We need to select partitions explicitly so
  that parallel runs work with hive/insert_overwrite
assert:
  - type: sql-select        # deterministic
    includes:
      snapshot_day:   "{{ snapshot_day }}"
      marketplace_id: "{{ marketplace_id }}"
Candidate A  ✓ passes
SELECT asin,
    '{{ snapshot_day }}'  AS snapshot_day, -- compiles to a literal
    {{ marketplace_id }}  AS marketplace_id -- e.g. 3 AS marketplace_id
FROM speed.shipments
WHERE marketplace_id = {{ marketplace_id }}
GROUP BY asin
Candidate B  ✗ fails
SELECT marketplace_id, -- read off the row
    CAST(ship_date AS date) AS ship_day,
    COUNT(DISTINCT asin) AS asins
FROM {{ source('speed','shipments') }}
GROUP BY marketplace_id, CAST(ship_date AS date)
Both look like reasonable dbt. Only A can run partitions in parallel without overwriting.

Takeaways

  1. Qualify the capabilities you need. Not the model.
  2. Make “good enough” executable
  3. Use the exam to build, not just to score

Start with one behaviour your AI must get right · turn it into an exam · make any implementation pass it
